02 / Runtime path

What happens on a review

Every application-specific answer is grounded in a database assessment before it reaches the reviewer.

01 / REQUEST

Reviewer selects an application

The dashboard calls GET /api/applications/{id}/assessment or refreshes the queue.

02 / ROUTE

FastAPI opens the data path

The API reads PostgreSQL using the configured DATABASE_URL and returns structured JSON.

03 / ASSESS

MCP tool calculates signals

The loan specialist uses assess_loan_application for DTI, credit, and employment indicators.

04 / REVIEW

Human makes the decision

The UI shows evidence and persists review state. It never auto-approves or rejects a person.

04 / Local operations

Start the connected stack

The API serves this same frontend, so one local URL is enough for the connected review experience.

Services

  • Start PostgreSQL with docker compose up -d postgres.
  • Install dependencies with py -m pip install -r requirements.txt.
  • Seed Chroma with py app/seed_knowledge.py.
  • Start the API with py -m uvicorn app.api:app --host 127.0.0.1 --port 8000.

Environment contract

  • DATABASE_URL points FastAPI and MCP to PostgreSQL.
  • CHROMA_PATH selects the local vector store.
  • LLM_BASE_URL and LLM_MODEL select local inference.
  • The UI falls back to demo data when the API cannot reach PostgreSQL.
Responsible use: loan signals are decision support, not an automated lending decision. Production deployment needs authentication, consent, audit logging, data-quality checks, fairness testing, and qualified human review.
